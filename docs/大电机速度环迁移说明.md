# MG680 大电机速度环迁移说明

## 结论

本工程的速度内环已经迁移为裸机实测版本的控制标准：

- 轮速公共单位：`mm/s`
- 系统采样节拍：`10 ms`
- 速度控制周期：`30 ms`（每 3 次采样计算一次）
- 控制器：位置式 PI，左右轮独立参数
- 逻辑 PWM 输出：`-4000..4000`，符号表示方向
- 轮径：`65 mm`
- 左轮输出轴计数：`2468.5 count/rev`
- 右轮输出轴计数：`2470.6 count/rev`
- 左轮 PI：`Kp=16, Ki=80, Kd=0`
- 右轮 PI：`Kp=16, Ki=80, Kd=0`
- 速度滤波：`alpha=0.70`

这些参数只在控制周期为 30 ms、速度误差单位为 mm/s、PWM 输出尺度为
0..4000 时具有原来的意义。不能直接填入旧的 RPM/50 ms/增量式 PID。

## 分层

1. `Component/config/motor_speed_profiles.*`
   保存可选择的电机档案。当前包含已验证的 MG680 大电机档案和不可启用的
   小电机模板。
2. `Component/control/speed_loop_core.*`
   只做编码器增量换算、滤波、方向切换保护和 PI 运算，不依赖 RTOS/硬件。
3. `Component/service/speed_service.*`
   管理 FreeRTOS 队列，读取编码器并把核心输出交给 TB6612。
4. `Component/tb6612/tb6612.*`
   把 `-4000..4000` 逻辑 PWM 映射到实际 2000 计数 PWM；在驱动内部处理
   “A 通道=物理右轮、B 通道=物理左轮”的板级映射。
5. `Component/task/app_tasks.*`
   对外直行接口使用 `app_tasks_set_wheel_speed_target_mm_s()`。

## 单位边界

速度内环从 app 到 control 全程使用 mm/s，变量名必须保留 `_mm_s` 后缀。
编码器 count 只允许进入 control 的采样接口，PWM count 只允许从 control 输出。

yaw 环目前仍保留原有 RPM 参数，避免尚未重新调试的角环参数被隐式改变。
`app_tasks.c` 在 yaw 输出进入速度服务前，通过
`large_motor_rpm_to_mm_s()` 做一次显式换算。这是临时兼容边界；将来重调 yaw
环时，应整体改为 mm/s，不能在不同层重复换算。

## 大电机与小电机档案

当前唯一选择点位于 `motor_speed_profiles.h`：

```c
#define MOTOR_SPEED_ACTIVE_PROFILE (&g_mg680_large_motor_profile)
```

每个档案封装以下信息：

- 档案名、电机型号、大/小电机类别、额定电压
- 轮径、减速比及其是否经过验证
- 电机轴编码器 CPR
- 左右输出轴实测 CPR 及其是否经过验证
- 左右驱动方向修正系数和已经实测的建议速度范围
- 采样周期、控制周期、滤波系数
- 左右独立 PID、积分限幅、换向阈值和 PWM 上限

MG680 的精确减速比和电机轴编码器 CPR 目前没有可靠依据，所以对应数值为
0，`gear_ratio_verified=false`。速度控制继续采用已经实测的输出轴 CPR，二者
不冲突。

小电机使用 `g_small_motor_template_profile`。该档案的未知数值全部为 0，且
`commissioned=false`。如果直接把它选为 active profile，
`speed_service_init()` 会失败并阻止电机启动。日后接入小电机时，应先填写：

1. 型号、供电电压和轮径；
2. 减速比及其来源，或左右输出轴实测 CPR；
3. 编码器计数方式；
4. 合适的采样/控制周期和 PWM 上限；
5. 小电机单独调出的左右 PID；
6. 完成架空验证后再设置 `commissioned=true`。

## 调用示例

```c
/* 两轮以 400 mm/s 前进。 */
app_tasks_set_wheel_speed_target_mm_s(400.0f, 400.0f);

/* 原地旋转。 */
app_tasks_set_wheel_speed_target_mm_s(-300.0f, 300.0f);

/* 停止。 */
app_tasks_set_wheel_speed_target_mm_s(0.0f, 0.0f);
```

## 首次上车验证顺序

1. 架空车轮，先下发 `+250 mm/s`，确认正值对应整车前进。
2. 在调试器观察 `speed_service_state_t` 的目标、实测和左右 PWM。
3. 依次验证 250、350、450、550 mm/s，不要第一次就满占空比。
4. 验证左右轮目标相同且实测接近，再接入 yaw 外环。
5. 若 RTOS 调度抖动使效果明显差于裸机，先测量 30 ms 实际执行间隔，不能先改 PI。

## 构建环境

- Arm Compiler 6.24
- MSPM0 SDK：`C:\ti\mspm0_sdk_2_10_00_04`
- SysConfig：`C:\ti\sysconfig_1.26.2`

Keil 工程使用上述 SDK 路径。换电脑时只需修改 `.uvprojx` 内两处 SDK 路径，
不要把硬件参数散落到 service 或 control 文件中。
