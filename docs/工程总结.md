# M0_Templant_FreeRTOS 工程总结

## 1. 工程概述

这是一个基于 **TI MSPM0G3507** 的 **FreeRTOS 工程模板**，使用 **Keil uVision** + **SysConfig** + **DriverLib** 开发。

当前工程已经从基础模板扩展为：

- LED 心跳灯 + 按键检测
- UART0 串口收发 / 周期发送
- SSD1306 OLED 显示（MPU 姿态 + 电机状态）
- MPU6050 DMP 姿态角读取
- TB6612 双路电机驱动（PWM 20kHz）
- FreeRTOS 多任务 + 队列通信
- MPU6050 INT 外部中断触发数据读取
- PA18 按键驱动电机状态机切换

## 3. SysConfig 配置原则

项目约定：**单片机外设一律使用 SysConfig 生成**。

当前 `main.syscfg` 中包含：

- `GPIO LED`
  - PB22 输出
- `GPIO_MPU6050_INT`
  - PB4 输入，内部上拉，下降沿中断，优先级 3
- `GPIO_OLED_SW_I2C`
  - PA28/PA31 输出（软件 I2C）
- `GPIO_TB6612`
  - PB17/PB19/PA16/PB24 输出（电机方向控制）
- `GPIO_KEY_MOTOR`
  - PA18 输入，内部下拉（电机测试按键）
- `GPIO_KEY_USER`
  - PB21 输入，内部上拉（用户按键）
- `I2C_0`
  - I2C0 Controller，PA0 SDA，PA1 SCL，100kHz
- `UART_0`
  - PA10 TX，PA11 RX，115200 baud
- `TIMER_0`
  - TIMG12，1ms 周期
- `PWM_TB6612`
  - TIMG0 边沿对齐 PWM，CC0=PA12，CC1=PA13
  - 40MHz BUSCLK，period=2000 → 20kHz

当前 `ti_msp_dl_config.h/.c` 已同步包含 PB4 中断和 PA0/PA1 I2C0 配置。

## 5. FreeRTOS 任务架构

当前任务：

| 任务 | 优先级 | 栈 | 功能 |
|---|---:|---:|---|
| `LED` | 1 | 128 | PB22 心跳闪烁 |
| `UART_Send` | 1 | 256 | 周期发送串口信息和堆信息 |
| `UART_Recv` | 1 | 256 | 串口接收回显 |
| `MPU` | 2 | 512 | 等待 MPU6050 INT 通知，读取姿态角 |
| `OLED` | 1 | 512 | 显示电机状态 + MPU 姿态角 |
| `TB6612_TEST` | 2 | 256 | PA18 按键切换电机状态 |

### 电机状态队列

```c
typedef enum {
    MOTOR_STOP = 0,
    MOTOR_FORWARD,
    MOTOR_BACKWARD,
    MOTOR_LEFT,
    MOTOR_RIGHT,
    MOTOR_STATE_COUNT
} motor_state_t;

static QueueHandle_t g_motor_state_queue = NULL;
```

TB6612_TEST 任务通过 PA18 按键循环切换状态，写入 `g_motor_state_queue`；OLED 任务非阻塞读取后显示。

### 姿态角队列

`main.c` 中定义：

```c
typedef struct {
    int status;
    float pitch10;
    float roll10;
    float yaw10;
} attitude_msg_t;

static QueueHandle_t g_attitude_queue = NULL;
```

队列长度为 1：

```c
g_attitude_queue = xQueueCreate(1, sizeof(attitude_msg_t));
```

MPU 任务使用：

```c
xQueueOverwrite(g_attitude_queue, &msg);
```

OLED 任务使用：

```c
xQueueReceive(g_attitude_queue, &msg, portMAX_DELAY);
```

这样 OLED 始终显示最新姿态角，不堆积旧数据。

## 6. MPU6050 INT 中断触发流程

### 数据流

```text
MPU6050 DMP 数据就绪
        ↓
PB4 INT 下降沿
        ↓
GROUP1_IRQHandler()
        ↓
vTaskNotifyGiveFromISR()
        ↓
mpu_task 被唤醒
        ↓
Read_Quad()
        ↓
xQueueOverwrite() 发送姿态角
        ↓
oled_task 显示
```

### 中断服务函数原则

ISR 中只做：

- 判断 PB4 中断来源
- 清除中断标志
- 通知 `mpu_task`

ISR 中**不做 I2C 访问**，避免在中断里阻塞或破坏 FreeRTOS 调度。

当前 ISR：

```c
void GROUP1_IRQHandler(void)
{
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;

    if (DL_GPIO_getPendingInterrupt(GPIO_MPU6050_INT_PORT) == GPIO_MPU6050_INT_IIDX) {
        DL_GPIO_clearInterruptStatus(GPIO_MPU6050_INT_PORT, GPIO_MPU6050_INT_PIN);
        if (g_mpu_task_handle != NULL) {
            vTaskNotifyGiveFromISR(g_mpu_task_handle, &xHigherPriorityTaskWoken);
        }
    }

    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}
```

### 中断优先级说明

PB4 属于 GPIOB/GROUP1 中断，当前配置：

```c
NVIC_SetPriority(GPIO_MPU6050_INT_IRQN, 3);
```

在本工程中：

```c
configLIBRARY_LOWEST_INTERRUPT_PRIORITY = 3
configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY = 1
```

因此 PB4 中断优先级为最低优先级，可以安全调用：

```c
vTaskNotifyGiveFromISR()
```

注意不要使用 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 直接传给 `NVIC_SetPriority()`，因为它是移位后的硬件优先级值；CMSIS `NVIC_SetPriority()` 需要未移位的逻辑优先级。

## 7. OLED 驱动现状

### 原始方案

早期 OLED 使用硬件 I2C0：

- PA28 SDA
- PA31 SCL

但 MPU6050 固定接线为：

- PA0 SDA
- PA1 SCL

PA0/PA1 与 PA28/PA31 都是 I2C0 的不同复用脚，不能同时作为两条独立硬件 I2C 使用。

### 当前方案

最终选择：

- MPU6050 使用硬件 I2C0：PA0/PA1
- OLED 使用软件 I2C：PA28/PA31

原因：

1. MPU6050 DMP 初始化和 FIFO 读取更依赖稳定 I2C。
2. OLED 显示频率低，软件 I2C 足够。
3. 避免 I2C0 在两组引脚之间动态切换带来的风险。

## 9. 已遇到的问题与结论

### 9.1 OLED 与 MPU6050 谁使用硬件 I2C

由于当前接线固定：

```text
OLED    -> PA28/PA31
MPU6050 -> PA0/PA1
```

最终结论：

```text
MPU6050 使用硬件 I2C0
OLED 使用软件 I2C
```

这样比 I2C0 在两组引脚间动态切换更稳定。

### 9.2 MPU/OLED 高优先级导致 LED/UART 不工作

早期 MPU 和 OLED 任务优先级高于 LED/UART，导致：

```text
MPU 高优先级读取
OLED 软件 I2C 刷屏
低优先级 LED/UART 饥饿
```

解决：

- LED、UART、OLED 当前均使用优先级 1，MPU 和 TB6612_TEST 使用优先级 2
- MPU 读取改为 INT 通知驱动，减少无意义轮询

### 9.3 ISR 不能直接读 MPU6050

参考工程在 GPIO 中断里直接 `Read_Quad()`，但本工程不采用这种方式。

原因：

- `Read_Quad()` 会访问 I2C
- I2C 可能等待/超时
- ISR 中不能执行阻塞型外设访问

当前采用：

```text
ISR 通知任务，任务读取 I2C
```

### 9.4 FreeRTOS 堆大小

由于增加了 MPU6050 DMP 驱动、多个任务、队列和串口缓冲，`FreeRTOSConfig.h` 中堆大小已调整为：

```c
#define configTOTAL_HEAP_SIZE ((size_t)(20 * 1024))
```

## 10. 当前工程状态

### 已正常保留/实现的功能

- LED 心跳任务
- 按键检测（PA18 电机测试 / PB21 预留）
- UART0 周期发送任务
- UART0 接收回显任务
- OLED 软件 I2C 显示任务（电机状态 + MPU 姿态）
- MPU6050 硬件 I2C0 初始化
- MPU6050 DMP 姿态角读取
- PB4 INT 中断通知 MPU 任务
- MPU 任务通过队列向 OLED 任务发送姿态数据
- TB6612 电机驱动（TIMG0 PWM 20kHz）
- PA18 按键驱动电机状态机（停止/前进/后退/左转/右转）

### 当前主流程

```text
main()
  ↓
prvSetupHardware()
  - SYSCFG_DL_init()
  - led_init()
  - key_init()
  - uart0_init()
  - tb6612_init()
  ↓
创建队列
  ↓
创建 LED / UART / MPU / OLED / TB6612_TEST 任务
  ↓
vTaskStartScheduler()
```

### OLED/MPU 初始化位置

- `MPU6050_Init()` 放在 `mpu_task()` 中
- `OLED_Init()` 放在 `oled_task()` 中

这样可以避免在调度器启动前执行耗时初始化，并方便任务级错误处理。

### OLED 显示布局

- 第 0 行：电机状态（STOP / FWD 70% / REV 70% / TURN L / TURN R）或 "MPU ERR"
- 第 1-3 行：Pitch / Roll / Yaw 姿态角

   - 可扩展用于自定义功能（如切换显示模式、急停等）。

## 13. 结论

当前工程已经形成较完整的：

```text
MSPM0G3507 + FreeRTOS + UART + OLED + MPU6050 DMP + TB6612 电机驱动
```

架构重点：

- 外设配置遵循 SysConfig
- MPU6050 使用硬件 I2C0
- OLED 使用软件 I2C，同时显示电机状态和 MPU 姿态
- MPU6050 INT 通过 PB4 中断通知任务
- I2C 读取放在任务中，不放在 ISR 中
- 任务间通过长度为 1 的队列传递最新数据
- TB6612 使用 TIMG0 双路 PWM 20kHz 驱动
- PA18 按键驱动电机状态机（停止→前进→后退→左转→右转→循环）
