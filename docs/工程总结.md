# M0_Templant_FreeRTOS 工程总结

## 1. 工程概述

本工程是基于 **TI MSPM0G3507** 的 FreeRTOS 小车控制工程，使用 **Keil uVision + SysConfig + DriverLib** 开发。

当前工程已经从基础模板扩展为：

- LED 心跳任务
- UART0 调试串口初始化与发送接口
- SSD1306 OLED 显示
- MPU6050 DMP 姿态角读取
- TB6612 双路直流电机驱动
- 双路增量编码器测速
- FreeRTOS 多任务、队列、任务通知
- 10ms 定时器触发的速度闭环任务
- 增量式 PID 双轮速度闭环
- PB21 按键循环切换 8 个速度档位

整体职责划分：

```text
main.c
  └─ 硬件初始化 + 启动 app_tasks_start()

Component/task/app_tasks.c
  └─ FreeRTOS 任务、队列、中断分发、速度闭环控制

Component/pid/pid.c
  └─ 整数增量式 PID 控制器
```

## 2. 当前硬件连接

### 2.1 LED 与按键

| 功能 | 引脚 | 说明 |
|---|---|---|
| LED | PB22 | 心跳指示灯 |
| KEY_USER | PB21 | 用户按键，内部上拉，按下低电平；当前用于速度档位切换 |

> 旧版文档中的 PA18 电机测试按键/状态机已经不再是当前主流程；当前速度控制入口是 PB21 档位切换以及 `app_tasks_set_wheel_speed_target()`。

### 2.2 UART0

| 功能 | 引脚 | 说明 |
|---|---|---|
| UART0_TX | PA10 | 115200 8N1 |
| UART0_RX | PA11 | 115200 8N1，RX 中断入队 |

UART0 当前主要用于启动信息和调试输出。完整串口在线调参逻辑建议保留在 `pid-debug-tuning` 分支，不建议长期放在生产版主流程中。

### 2.3 MPU6050

| 功能 | 引脚 | 说明 |
|---|---|---|
| SDA | PA0 | 硬件 I2C0 SDA |
| SCL | PA1 | 硬件 I2C0 SCL |
| INT | PB4 | DMP 数据就绪中断，下降沿触发 |

### 2.4 OLED SSD1306

| 功能 | 引脚 | 说明 |
|---|---|---|
| SDA | PA28 | 软件 I2C SDA |
| SCL | PA31 | 软件 I2C SCL |

当前固定方案：

```text
MPU6050 使用硬件 I2C0：PA0/PA1
OLED 使用软件 I2C：PA28/PA31
```

原因是 PA0/PA1 与 PA28/PA31 都属于 I2C0 的可复用引脚组合，不能同时作为两条独立硬件 I2C 总线使用。

### 2.5 TB6612 电机驱动

| 功能 | 引脚 | 说明 |
|---|---|---|
| PWMA | PA12 | PWM_TB6612 CC0 |
| PWMB | PA13 | PWM_TB6612 CC1 |
| AIN1 | PB17 | 电机 A 方向控制 |
| AIN2 | PB19 | 电机 A 方向控制 |
| BIN1 | PA16 | 电机 B 方向控制 |
| BIN2 | PB24 | 电机 B 方向控制 |
| STBY | +5V | 硬件拉高使能 |

实测接线注意：

```text
TB6612 电机 A -> 物理右轮
TB6612 电机 B -> 物理左轮
```

因此速度闭环输出时使用：

```c
tb6612_set_speed(right_pwm, left_pwm);
```

### 2.6 编码器

| 功能 | 引脚 | 说明 |
|---|---|---|
| QEI A | PA26 | TIMG8 QEI 通道 A |
| QEI B | PA27 | TIMG8 QEI 通道 B |
| GPIO A | PA25 | GPIO 双边沿软件解码 |
| GPIO B | PA14 | GPIO 双边沿软件解码 |

`encoder_get_data()` 内部已经处理了硬件通道与物理左右轮的映射，应用层直接使用 `left_delta/right_delta` 即可。

编码器参数：

```c
#define ENCODER_COUNTS_PER_REV 440
```

## 5. FreeRTOS 任务架构

当前主要任务：

| 任务 | 优先级 | 栈 | 触发源 | 功能 |
|---|---:|---:|---|---|
| `LED` | 1 | 128 | 500ms 周期 | 心跳灯 |
| `MPU` | 2 | 512 | MPU6050 INT 任务通知 | DMP 姿态读取 |
| `SPD_LOOP` | 3 | 512 | TIMER_0 10ms 任务通知 | 编码器采样 + 50ms PID 速度闭环 |
| `GEAR` | 2 | 192 | 10ms 轮询 | PB21 按键切换速度档位 |
| `OLED` | 1 | 512 | 100ms 周期 | 显示档位、目标速度、实测速度、PWM |
| `DEBUG` | 1 | 256 | 50ms 周期 | 如启用，用于串口波形输出 |

> `DEBUG` 任务属于调试辅助。生产版可删除该任务和对应串口输出；完整串口在线调参代码建议保留在 `pid-debug-tuning` 分支。

### 5.1 队列

当前使用 3 个长度为 1 的队列：

```c
static QueueHandle_t g_attitude_queue;
static QueueHandle_t g_status_queue;
static QueueHandle_t g_target_speed_queue;
```

用途：

| 队列 | 生产者 | 消费者 | 内容 |
|---|---|---|---|
| `g_attitude_queue` | `mpu_task` | 预留/后续平衡任务 | MPU6050 姿态角 |
| `g_status_queue` | `speed_loop_task` | `oled_task` / 调试输出 | 速度闭环状态快照 |
| `g_target_speed_queue` | `speed_gear_task` / 外部接口 | `speed_loop_task` | 左右轮目标速度 |

均采用覆盖式写入，保证消费者拿到最新状态，不堆积旧数据。

### 5.2 外部速度目标接口

`Component/task/app_tasks.h` 暴露：

```c
bool app_tasks_set_wheel_speed_target(int32_t left_rpm, int32_t right_rpm);
```

用途：

```c
// 直行
app_tasks_set_wheel_speed_target(200, 200);

// 差速转向
app_tasks_set_wheel_speed_target(-100, 100);

// 停止
app_tasks_set_wheel_speed_target(0, 0);
```

后续巡线、角度控制、平衡控制任务可以统一通过该接口下发左右轮目标速度。

## 6. 速度闭环控制

### 6.1 控制链路

```text
TIMER_0 10ms 中断
        ↓
vTaskNotifyGiveFromISR(g_speed_loop_task_handle)
        ↓
speed_loop_task 唤醒
        ↓
encoder_get_data() 读取 10ms 编码器增量
        ↓
累计 5 次，即 50ms 窗口
        ↓
编码器增量 -> RPM × 10
        ↓
一阶低通滤波
        ↓
速度目标斜坡 setpoint
        ↓
左右轮独立增量式 PID
        ↓
tb6612_set_speed(right_pwm, left_pwm)
        ↓
状态写入 g_status_queue
```

### 6.2 控制周期

```c
#define ENCODER_SPEED_PERIOD_MS 10
```

速度计算与 PID 更新周期：

```text
5 × 10ms = 50ms
```

选择 50ms 的原因：

- 低速下 10ms 编码器计数太少，速度量化误差明显。
- 50ms 累积窗口可以获得更稳定的 RPM 估计。
- 对当前直流减速电机速度环响应足够。

### 6.3 RPM 计算

```c
rpm10 = delta * 600000 / (ENCODER_COUNTS_PER_REV * period_ms)
```

其中：

```text
600000 = 60s/min × 1000ms/s × 10
```

内部使用 `int64_t` 防止乘法溢出。

### 6.4 速度滤波

当前一阶低通滤波：

```c
filtered += (raw - filtered) / 2;
```

也就是：

```text
filtered_new = 0.5 × raw + 0.5 × filtered_old
```

用于降低编码器量化噪声和瞬时跳变。

### 6.5 速度目标斜坡

当前加入了目标速度斜坡：

```c
#define SPEED_RAMP_STEP_RPM 30
```

每个 50ms 控制周期，内部 setpoint 最多变化 30 RPM。

作用：

- 减少 `+400 -> -20` 或正反转切换时的机械冲击。
- 避免 PID 直接吃阶跃目标造成输出突变。
- 普通换档不再一律 reset PID，提升输出连续性。

目标为 0 时会清零 setpoint、复位 PID 并停止电机。

## 7. PID 控制器

### 7.1 默认参数

当前速度环默认参数：

```c
#define PID_DEFAULT_KP_MILLI 80   // Kp = 0.080
#define PID_DEFAULT_KI_MILLI 50   // Ki = 0.050
#define PID_DEFAULT_KD_MILLI 0    // Kd = 0
#define PID_OUTPUT_MIN      (-80)
#define PID_OUTPUT_MAX      (80)
```

调试结果：

- 低速 60/80 RPM 基本无稳态误差。
- 反向阶跃超调较小。
- D 项关闭，避免放大编码器速度量化噪声。

### 7.2 增量式 PID 公式

```text
Δu[k] = Kp × (e[k] - e[k-1])
      + Ki × e[k]
      + Kd × (e[k] - 2e[k-1] + e[k-2])

u[k] = clamp(u[k-1] + Δu[k], out_min, out_max)
```

误差：

```text
e[k] = target - measured
```

### 7.3 整数实现

PID 参数使用千倍整数：

```text
kp_milli = Kp × 1000
ki_milli = Ki × 1000
kd_milli = Kd × 1000
```

内部使用：

```c
int32_t output_milli;
```

保留输出小数累计，避免整数截断导致低速控制不连续。

### 7.4 已修正的限幅逻辑

当前 `pid_inc_compute()` 使用：

```c
next_milli = output_milli + delta_milli;
output_milli = clamp(next_milli, min_milli, max_milli);
```

不再采用“超过限幅就把本次增量清零”的做法。

这样输出可以正常到达 `out_min/out_max`，不会在接近限幅时提前削弱响应。

### 7.5 电机死区处理

当前 PID 内部不做电机死区过滤，PID 保持纯净。

如果后续需要处理低速死区，建议放在电机输出层做前馈/静摩擦补偿，例如：

```text
final_pwm = pid_output + sign(target) × static_friction_pwm
```

不要在 PID 内部直接把小输出清零，否则容易破坏积分连续性。

## 9. MPU6050 与中断流程

### 9.1 数据流

```text
MPU6050 DMP 数据就绪
        ↓
PB4 下降沿
        ↓
GROUP1_IRQHandler()
        ↓
vTaskNotifyGiveFromISR(g_mpu_task_handle)
        ↓
mpu_task 唤醒
        ↓
Read_Quad()
        ↓
写入 g_attitude_queue
```

### 9.2 ISR 原则

ISR 中只做：

- 判断中断来源
- 清中断标志
- 通知对应任务

不在 ISR 中做 I2C 访问。

原因：

- I2C 读写可能等待或超时。
- ISR 中阻塞会破坏实时性。
- FreeRTOS 下外设访问应放在任务上下文。

### 9.3 GROUP1 中断复用

`GROUP1_IRQHandler()` 当前分发两个来源：

1. 右轮编码器 GPIO 双边沿中断
2. MPU6050 INT 数据就绪中断

处理顺序：

```text
encoder_right_int_is_pending()
  -> encoder_right_irq_handler()

MPU6050_IntIsPending()
  -> MPU6050_IntClear()
  -> vTaskNotifyGiveFromISR(g_mpu_task_handle)
```

## 10. OLED 显示

OLED 使用 PA28/PA31 软件 I2C。

当前主要显示速度闭环状态：

```text
第 0 行：GEAR: n 或 GEAR: STOP
第 1 行：T:left_target/right_target
第 2 行：L:left_rpm/left_pwm
第 3 行：R:right_rpm/right_pwm
```

刷新周期：

```text
100ms
```

注意：OLED 软件 I2C 刷屏耗时较长，因此 OLED 任务优先级保持较低，避免影响速度闭环任务。

## 12. 已遇到的问题与结论

### 12.1 OLED 与 MPU6050 的 I2C 冲突

问题：

```text
OLED    -> PA28/PA31
MPU6050 -> PA0/PA1
```

两组引脚都是 I2C0 的复用方案，不能同时作为两路硬件 I2C。

结论：

```text
MPU6050 使用硬件 I2C0
OLED 使用软件 I2C
```

### 12.2 ISR 不能直接读 MPU6050

`Read_Quad()` 涉及 I2C 访问，不能放在 GPIO ISR 中。

当前方案：

```text
ISR 只通知任务，mpu_task 中读取 I2C
```

### 12.3 编码器测速量化噪声

低速时 10ms 窗口内脉冲数少，RPM 抖动明显。

当前方案：

- 10ms 读取编码器增量
- 50ms 累计窗口计算 RPM
- 一阶低通滤波
- D 项默认关闭

### 12.4 正反转切换冲击

原始阶跃目标容易在正反转切换时产生冲击。

当前方案：

- 目标速度通过 `SPEED_RAMP_STEP_RPM = 30` 斜坡过渡
- 普通换档不一律 reset PID
- 目标为 0 时才立即停止并 reset

### 12.5 PID 输出限幅

原先如果“下一步输出超过限幅就清零本次增量”，可能导致输出到不了限幅边界。

当前方案：

```text
先累加，再 clamp
```

这样输出响应更自然。

## 14. 后续建议

1. **生产版清理 DEBUG 任务**
   - 如不需要串口波形输出，可删除 `debug_print` 任务和 `app_tasks.c` 中对 `uart0.h/stdio.h` 的依赖。

2. **保留调参分支**
   - `pid-debug-tuning` 分支保留完整串口调参能力，后续换电机、换负载、换电池后可以继续使用。

3. **低速死区补偿**
   - 如落地后 20 RPM 档位起步困难，建议在电机输出层加静摩擦前馈，不要在 PID 内部清零小输出。

4. **左右轮标定**
   - 若落地后左右轮速度偏差明显，可分别设置左右轮 PID 参数或加入左右轮前馈修正。

5. **上层控制扩展**
   - 巡线、姿态角修正、速度规划等上层任务统一调用：
     ```c
     app_tasks_set_wheel_speed_target(left_rpm, right_rpm);
     ```

核心架构特点：

- 外设配置遵循 SysConfig
- `main.c` 只负责硬件初始化和启动调度器
- 任务间通过队列/任务通知松耦合通信
- MPU6050 I2C 读取放在任务中，不放在 ISR 中
- 速度环由 10ms 定时器触发，50ms 更新 PID
- 增量式 PID 使用整数千倍参数和高精度 `output_milli`
- 目标速度斜坡降低换档和反向冲击
- 调试代码与生产逻辑建议通过 Git 分支隔离
