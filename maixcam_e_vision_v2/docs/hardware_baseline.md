# 第 2 步：相机与 UART0 实机基准

本步骤不识别靶标、不识别激光、不控制电机。目标是确认相机、UART0、MSPM0 接收端和供电在最小链路下稳定。

## 运行前检查

1. MaixCAM `/boot/configs` 已设置 `maix_comm_method=none` 并完成重启。
2. 默认只连接 A16 → MSPM0_RX 和 GND；A17 保持不接。
3. MSPM0 设置为 UART0、115200、8N1、无流控，并过滤 UART0 启动日志。
4. MSPM0 收到 `AIM,0,...,LOST,LOST` 时不得更新电机瞄准误差。
5. 先运行 `tools/camera_preview.py`，确认画面稳定且没有循环重启。

## 基准运行方法

在 `config.py` 设置 `CAMERA_BENCHMARK_INDEX`，每次仅测试一个候选分辨率：

| 索引 | 分辨率 | 请求帧率 |
|---:|---:|---:|
| 0 | 320×240 | 60 |
| 1 | 512×320 | 60 |
| 2 | 448×448 | 60 |

运行 `tools/hardware_baseline.py`。程序完成预热后抓取 300 帧，并每 6 帧发送一次安全 LOST 测试帧；串口输出一行 `BASELINE,...` 结果。

其中 `read_p50_us/read_p95_us` 是单次相机 `read()` 的耗时，`cycle_p50_us/cycle_p95_us` 是相邻处理帧之间的耗时，`uart_write_*` 是 MaixCAM 调用串口写入接口的耗时。它们是 MaixCAM 端性能基准，不等于完整端到端延迟。

端到端延迟需要另行测量：在可见画面中制造清晰事件，同时由 MSPM0 对第一帧合法 AIM 的接收时刻打点；记录两者时间差。A16 单向接线时不能由 MaixCAM 自动读取这个结果。

## 通过条件

- 三种分辨率均能完成预热、抓帧和 UART 测试，无循环重启。
- MSPM0 只解析完整 AIM 帧，不把开机日志当成数据。
- 记录每种分辨率的实测 FPS、相机读取耗时、处理周期、串口调用耗时、端到端延迟和主控接收情况。
- 最终分辨率在记录完成前不确定；不得仅以屏幕 FPS 选择。

相机 `buff_num=1` 用于降低延迟，但 MaixCAM 内部仍可能存在 30 ms 以上的取图延迟。最终端到端结果必须以实测为准。
